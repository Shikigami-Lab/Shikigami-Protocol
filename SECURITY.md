# Security policy

## Reporting a vulnerability

Do **not** open a public issue for exploitable security problems (RCE, credential theft, unsafe defaults that enable remote compromise of the host, etc.).

**Preferred:** use GitHub **Private vulnerability reporting** for this repository, if enabled:

`https://github.com/Shikigami-Lab/Shikigami-Protocol/security/advisories/new`

If that is not available, open a **draft** Security Advisory with minimal reproduction details, or contact maintainers through a non-public channel they publish on the repo/org profile.

Include: affected version or commit, environment (OS, install path: release binary vs source), and steps to reproduce.

## Scope

- **In scope:** this repository, default configuration as shipped, and first-party code under `src/`, `server.py`, `main.js`, and packaged assets.
- **Out of scope:** third-party LLM / TTS / STT APIs and their terms; content generated by user-configured models; issues that require the user to paste API keys into public issues (rotate keys instead).

## Disclosure

We try to acknowledge reports within a few business days. This project is volunteer-maintained; fix timelines depend on severity and availability.

This document is operational guidance only, not a legal commitment.
